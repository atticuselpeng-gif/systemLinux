A source-based system needs little maintenance, but a few habits keep it healthy.

Backups

Keep a copy of what cannot be downloaded again: /home, /etc and anything else you made. Everything installed with get can be rebuilt from get list. A simple copy to an external disk:

$ sudo get install rsync                 # if it is not there yet
$ sudo rsync -aAXH --delete /home /etc /mnt/backup/
$ get list | awk '$1=="*"{print $2}' > ~/packages.txt   # what you installed on purpose

On an image install everything that is yours is in /persist/upper on the system partition.

Updating software

$ sudo get sync                          # the newest ports tree
$ get info NAME                          # compare its version with get list
$ sudo get install -f NAME               # rebuild NAME at the new version

There is no command to rebuild every outdated package yet. Rebuild the packages that matter to you, and above all those exposed to the network (browsers, SSH, mail clients) when a security fix is out.

Moving to a new release

A release brings a new base system: new libraries, a new kernel and a new initramfs. There is no in-place upgrade of the base system yet. You can:

  • Update the kernel only: copy the kernel, its modules and the initramfs from the new stage, see Kernel.
  • Reinstall: back up, install the new release with the Handbook (keep a separate /home partition and do not format it), and rebuild your packages from packages.txt: sudo get install $(cat ~/packages.txt).

Cleaning up

$ sudo get autoremove                    # dependencies nothing needs any more
$ sudo find /etc -name '*.get-new'       # new configuration files waiting to be merged
$ du -sh /var/tmp /tmp                   # leftover build directories after -k

Disks

  • Trim SSDs once a week: sudo fstrim -av.
  • Check the free space before big builds: df -h /.
  • Check a disk's health: sudo get install smartmontools, then sudo smartctl -a /dev/sda.

Logs and errors

Look at the kernel's messages with dmesg (sudo dmesg -w follows them), and at failed services with dinitctl list. There is no journal; see dinit.
