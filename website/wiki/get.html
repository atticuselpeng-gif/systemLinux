get is the systemLinux package tool. It builds software from source using the recipes in the ports tree, installs it into /usr, and records every file it installs so it can remove exactly those files again. It is one POSIX shell script, /usr/local/bin/get.

Usage

CommandWhat it does
get install NAME...build and install NAME and everything it needs (aliases: i, add)
get remove NAME...uninstall NAME; refused while another package needs it (rm, uninstall)
get autoremoveremove dependencies that nothing needs any more
get listinstalled packages; * marks those you asked for, the rest are dependencies (ls)
get search WORDfind ports by name or description (s)
get info NAMEthe recipe, dependencies and whether it is installed (show)
get files NAMEthe files an installed package owns
get syncreplace the ports tree with the one of the latest release (update)
get install URLbuild a source tarball that has no recipe
get profile NAMEunpack a prebuilt package profile

Options, before or after the command:

-f, --force
install even if already installed or provided by the base system (rebuilds it); remove even if needed
-j N
number of parallel build jobs (default: the number of CPUs)
-k, --keep
keep the build directory, to look at a failed build

Installing, removing, syncing and profiles need root: run them with sudo. Searching and listing do not.

Installing software

$ get search editor
$ get info neovim
$ sudo get install neovim
==> 3 package(s) to build: dev-libs/libuv dev-libs/luajit dev-apps/neovim
...
==> done

A NAME is a port name (neovim) or, when two categories have a port of the same name, the full category/name (dev-apps/neovim). get works out the dependencies from the recipes' requires lines and builds them first, in order. Anything the base system already provides is not rebuilt.

Prebuilt programs (-bin ports)

Ports whose name ends in -bin install the project's own official build instead of compiling it. They are the fast way to get very big programs: sudo get install firefox-bin takes a minute, building firefox takes hours.

Tarballs without a recipe

get builds most source tarballs directly, detecting the build system (configure, CMake, Meson, plain make, ...):

$ sudo get install https://ftp.gnu.org/gnu/hello/hello-2.12.2.tar.gz
$ get list
* url/hello-2.12.2

Such packages are tracked as url/NAME and removed the same way: sudo get remove url/hello-2.12.2. Their dependencies are not resolved; install those first.

Removing software

$ sudo get remove neovim
$ sudo get autoremove                    # libuv and luajit, if nothing else needs them

get remove deletes exactly the files that were installed (see get files NAME), its files in /etc included, and the directories it leaves empty. Back up a configuration file you edited before you remove its package. Packages that replaced a base package, or that others need, are only removed with -f.

Updating

There is no "upgrade everything" command yet. To update a package, update the ports tree and rebuild it:

$ sudo get sync
$ get info neovim                        # the version in the new tree
$ sudo get install -f neovim

How files are handled

  • Packages install into /usr, configuration into /etc, state into /var, like the base system.
  • A package never silently overwrites a file that belongs to another package. The base system's files are recorded too, as base/NAME; a port with the same name as a base package replaces it in place.
  • If a configuration file in /etc already exists, yours is kept and the new one is installed next to it as FILE.get-new. Compare them and merge by hand.
  • Ports that come with a dinit service install it into /etc/dinit.d and tell you how to enable it.

Files and directories

PathContents
/usr/portsthe ports tree (GET_PORTS overrides it)
/var/db/get/pkgs/one directory per installed package: its file list, version and whether you asked for it
/usr/share/systemlinux/base-packagesthe packages the base system provides
$TMPDIR (default /tmp)build directories, deleted after each build

Tips and tricks

Big builds and /tmp

/tmp is in memory and only half the size of your RAM. Build big packages on disk instead:

$ sudo TMPDIR=/var/tmp get install firefox

Fewer build jobs

Large C++ projects use about 2 GB of memory per job. If a build is killed (look for "Killed" or "out of memory" in the output), use fewer jobs: sudo get install -j 2 NAME.

Installing into your home directory

With GET_PREFIX get installs somewhere else and does not need root:

$ GET_PREFIX=$HOME/.local GET_DB=$HOME/.local/var/db/get get install htop

Troubleshooting

A build fails

Run it again with -k to keep the build directory, read the first error in the output, and open an issue with the port name and that error. Many ports are not verified yet; reports are how they get fixed.

unknown package

The port does not exist in your tree. Run sudo get sync and search again, or write a port.

'NAME' is ambiguous

Two categories have a port with that name; use the category/name form that get prints.
