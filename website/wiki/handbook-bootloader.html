systemLinux uses GRUB. It is in the stage, for both UEFI and legacy BIOS. All commands run inside the chroot.

Installing GRUB

UEFI

The EFI System Partition must be mounted on /boot/efi (chapter 6).

(chroot) # grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=systemLinux
Installing for x86_64-efi platform.
Installation finished. No error reported.

This puts GRUB in /boot/efi/EFI/systemLinux/, its modules in /boot/grub/, and adds a "systemLinux" entry to the firmware's boot menu. Some firmware ignores entries it did not create itself and only starts the fallback path \EFI\BOOT\BOOTX64.EFI. Install there as well, so the disk boots anyway:

(chroot) # grub-install --target=x86_64-efi --efi-directory=/boot/efi --removable
Warning: On a disk shared with Windows, --removable replaces whatever was in \EFI\BOOT\. That is usually a copy of the Windows boot manager and harmless to replace, but leave it out if you are not sure; the first command is enough on most computers.

If grub-install says "EFI variables are not supported on this system", you booted the live ISO in BIOS mode: reboot it in UEFI mode, or use the BIOS instructions below.

Legacy BIOS

GRUB goes to the start of the disk (not a partition) and into the BIOS boot partition:

(chroot) # grub-install --target=i386-pc /dev/sda
Installing for i386-pc platform.
Installation finished. No error reported.

Both

With the layout that has both a BIOS boot partition and an ESP, run the UEFI commands and the BIOS command. The same grub.cfg serves both.

Writing grub.cfg

GRUB's menu is /boot/grub/grub.cfg. systemLinux has no grub-mkconfig; the menu is a short file you write once. It needs the UUID of the root file system:

(chroot) # ROOTUUID=$(blkid -s UUID -o value /dev/sda2)
(chroot) # echo $ROOTUUID
(chroot) # cat > /boot/grub/grub.cfg <<EOF
set timeout=3
set default=0
insmod part_gpt
insmod ext2

menuentry "systemLinux" {
    search --no-floppy --fs-uuid --set=root $ROOTUUID
    linux /boot/vmlinuz root=UUID=$ROOTUUID quiet loglevel=3
    initrd /boot/initrd.img
}

menuentry "systemLinux (show all boot messages)" {
    search --no-floppy --fs-uuid --set=root $ROOTUUID
    linux /boot/vmlinuz root=UUID=$ROOTUUID
    initrd /boot/initrd.img
}
EOF
(chroot) # cat /boot/grub/grub.cfg

search tells GRUB which partition to read the kernel from; root= tells the initramfs which partition to mount as /. Here they are the same partition. ext2 is GRUB's module for ext2, ext3 and ext4.

Check that the UUID was filled in: an empty root=UUID= means ROOTUUID was not set.

With a separate /boot and an encrypted root

GRUB reads the kernel from the /boot partition, where it sits at the top (/vmlinuz), and root= names the encrypted partition. The initramfs sees that it is LUKS, asks for the passphrase and mounts what is inside:

(chroot) # BOOTUUID=$(blkid -s UUID -o value /dev/sda2)
(chroot) # LUKSUUID=$(blkid -s UUID -o value /dev/sda3)
(chroot) # cat > /boot/grub/grub.cfg <<EOF
set timeout=3
insmod part_gpt
insmod ext2

menuentry "systemLinux" {
    search --no-floppy --fs-uuid --set=root $BOOTUUID
    linux /vmlinuz root=UUID=$LUKSUUID quiet loglevel=3
    initrd /initrd.img
}
EOF

Kernel options

Add options to the linux line. Common ones: console=ttyS0,115200 for a serial console, rootflags=... for root mount options, rootfstype=xfs to skip file system detection. The full list is in Kernel parameters.

Other systems

To start Windows or another Linux from GRUB's menu, add an entry for it: see Dual boot.
