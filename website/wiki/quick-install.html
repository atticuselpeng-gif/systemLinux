systemlinux-install is the installer on the live ISO. It asks a few questions and installs the system in a few minutes. Use it if you do not want to go through the Handbook.

Note: The quick installer still makes the older image install: the system runs from the compressed image of the release, and your changes are kept in a writable layer on top of it (/persist). A Handbook install is an ordinary writable root instead. The installer will switch to stage installs in a future release.

Running it

Boot the ISO (Installation media, Booting the live system) and run:

# systemlinux-install

It asks, one question at a time:

  1. [d]isk or [p]artition: d erases a whole disk, p installs into one partition and leaves the rest of the disk alone (Dual boot). It lists the disks first.
  2. The disk or partition, e.g. /dev/sda, /dev/nvme0n1, /dev/vda.
  3. Computer name (default systemlinux).
  4. User name: lowercase letters, digits, - and _. This account may use sudo.
  5. Full name (optional).
  6. Time zone, e.g. Europe/Paris (default UTC).
  7. Console keymap, e.g. us, fr, de.
  8. Password, twice, and whether root gets the same one.
  9. Encrypt with LUKS? and then a passphrase, twice.

It shows what it will erase and waits until you type yes. Nothing is written before that. It ends with "Done. Remove the installation media and reboot."

Without questions

Every answer can be given on the command line, for scripted installs:

# systemlinux-install --disk /dev/sda --host laptop --user alex --tz Europe/Paris --keymap fr --yes
# systemlinux-install --partition /dev/nvme0n1p5 --esp /dev/nvme0n1p1 --user alex
--disk DISK
erase DISK: GPT with a 1 MiB BIOS boot partition, a 512 MiB EFI System Partition and one ext4 partition for the rest. GRUB is installed for both UEFI and BIOS.
--partition PART [--esp ESP]
format only PART. On UEFI an existing EFI System Partition is reused; with several, name it with --esp. On BIOS, GRUB goes to the disk's boot code.
--host, --user, --tz, --keymap
the answers to the questions above
--luks
encrypt the system partition. GRUB then has to unlock it itself to read the kernel, and GRUB 2.12 cannot open LUKS2 volumes that use cryptsetup's default Argon2 key function, so this option is not reliable yet. For encryption, use the Handbook layout with a separate /boot.
--yes
do not ask for confirmation

What it creates

The system partition holds /boot/images/VERSION/ (kernel, initramfs, rootfs.squashfs), /boot/grub and /persist. At boot the initramfs mounts the image read-only and puts /persist/upper on top of it as a writable layer; everything you change or install ends up there. Recovery explains how to reach it from the live system.
