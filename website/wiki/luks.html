Disk encryption (LUKS)

Related articles
  • 3. Preparing the disks
  • Initramfs
  • GRUB
Contents
  1. 1 Layout
  2. 2 At boot
  3. 3 Managing keys
    1. 3.1 Header backup
  4. 4 Other encrypted disks
  5. 5 Opening from the live ISO

LUKS encrypts a whole partition. Without the passphrase its contents are unreadable, which protects your data if the computer or the disk is stolen. systemLinux's initramfs unlocks an encrypted root partition at boot.

Layout

The kernel and the initramfs must be readable before anything is unlocked, so they live on a small unencrypted /boot partition. Everything else is in the encrypted root:

PartitionContents
EFI System Partition (UEFI) or BIOS bootGRUB
/boot, ext4, 1 GiB, not encryptedkernel, initramfs, GRUB's modules and menu
LUKS partition, rest of the diskthe root file system, opened as /dev/mapper/root

The Handbook sets this up step by step. The commands:

# cryptsetup luksFormat /dev/sda3
# cryptsetup open /dev/sda3 root
# mkfs.ext4 /dev/mapper/root

In /etc/fstab the root line uses /dev/mapper/root, and in grub.cfg root=UUID= names the LUKS partition itself (blkid -s UUID -o value /dev/sda3):

linux /vmlinuz root=UUID=<UUID of /dev/sda3> quiet
Why not encrypt /boot too? GRUB would have to unlock the disk itself. GRUB 2.12 cannot open LUKS2 volumes made with cryptsetup's default key derivation (Argon2id), and asking for the passphrase twice (GRUB, then the initramfs) is clumsy. The kernel is not secret; an unencrypted /boot is the common setup.

At boot

[live] encrypted root partition: enter the passphrase to unlock it
Enter passphrase for /dev/sda3:

A wrong passphrase asks again. The console uses the US layout at this point: if your passphrase has characters that are elsewhere on your keyboard, type them where they are on a US keyboard, or choose a passphrase without them.

Managing keys

A LUKS partition has up to 32 key slots; each one opens it. Add a second passphrase as a backup before you change anything:

$ sudo cryptsetup luksAddKey /dev/sda3          # asks for an existing passphrase, then the new one
$ sudo cryptsetup luksChangeKey /dev/sda3       # replace a passphrase
$ sudo cryptsetup luksRemoveKey /dev/sda3       # remove a passphrase (type the one to remove)
$ sudo cryptsetup luksDump /dev/sda3            # slots and settings

Header backup

If the LUKS header at the start of the partition is damaged, the data is lost even with the passphrase. Keep a copy somewhere else (not on the encrypted disk):

$ sudo cryptsetup luksHeaderBackup /dev/sda3 --header-backup-file /mnt/usb/sda3-luks-header.img

Other encrypted disks

A second encrypted disk (for example /home or data) is opened by hand after login:

$ sudo cryptsetup open /dev/sdb1 data
$ sudo mount /dev/mapper/data /data

There is no /etc/crypttab support yet.

Opening from the live ISO

# cryptsetup open /dev/sda3 root
# mount /dev/mapper/root /mnt
