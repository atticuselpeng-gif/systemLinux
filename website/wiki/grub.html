GRUB is the bootloader systemLinux installs: the program the firmware starts, which shows a menu, loads the kernel and the initramfs from disk and starts the kernel. It works on UEFI and on legacy BIOS computers.

Installation

FirmwareCommandWhere GRUB goes
UEFIgrub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=systemLinux/boot/efi/EFI/systemLinux/grubx64.efi and a firmware boot entry
UEFI fallbackgrub-install --target=x86_64-efi --efi-directory=/boot/efi --removable/boot/efi/EFI/BOOT/BOOTX64.EFI, which firmware starts when it has no entry
BIOSgrub-install --target=i386-pc /dev/sdathe disk's first sector and the BIOS boot partition (GPT) or the gap after the first sector (MBR)

In every case the modules and the menu are in /boot/grub/. Run grub-install again after replacing a disk's partition table, or when another system's installer took over the boot.

Configuration

systemLinux has no grub-mkconfig: /boot/grub/grub.cfg is a file you write and edit. A complete example with two kernels and a Windows entry:

set timeout=5
set default=0
insmod part_gpt
insmod ext2

menuentry "systemLinux" {
    search --no-floppy --fs-uuid --set=root 0f4c...e1
    linux /boot/vmlinuz root=UUID=0f4c...e1 quiet loglevel=3
    initrd /boot/initrd.img
}

menuentry "systemLinux (previous kernel)" {
    search --no-floppy --fs-uuid --set=root 0f4c...e1
    linux /boot/vmlinuz.old root=UUID=0f4c...e1
    initrd /boot/initrd.img.old
}

menuentry "Windows" {
    insmod fat
    search --no-floppy --fs-uuid --set=root A1B2-C3D4
    chainloader /EFI/Microsoft/Boot/bootmgfw.efi
}

menuentry "Firmware settings" {
    fwsetup
}
set timeout=N
seconds before the default entry starts; -1 waits forever, 0 skips the menu (hold Shift or press Esc to see it)
set default=N
the entry started by default, counted from 0
search --fs-uuid --set=root UUID
the partition the following paths refer to
linux PATH OPTIONS
the kernel and its parameters
initrd PATH
the initramfs
chainloader PATH
start another EFI program (Windows' boot manager)

Changes take effect at the next boot; there is nothing to regenerate. Make a copy before you edit (sudo cp /boot/grub/grub.cfg /boot/grub/grub.cfg.bak): if GRUB cannot read the file, it stops at a grub> prompt.

Image installs

On a quick install, grub.cfg is written by systemlinux-grubcfg with one entry per image in /boot/images. The default entry is remembered in /boot/grub/grubenv: grub-set-default VERSION changes it and grub-reboot VERSION picks an entry for the next boot only.

Troubleshooting

The grub> or grub rescue> prompt

GRUB started but cannot find or read its menu. Boot by hand from the prompt:

grub> ls                                     # the partitions: (hd0,gpt1) (hd0,gpt2) ...
grub> ls (hd0,gpt2)/boot                     # find the one with vmlinuz
grub> set root=(hd0,gpt2)
grub> linux /boot/vmlinuz root=/dev/sda2
grub> initrd /boot/initrd.img
grub> boot

Then fix /boot/grub/grub.cfg, or run grub-install again. "grub rescue>" means GRUB could not even load its modules: reinstall it from the live ISO (Recovery).

The computer boots straight into Windows or another system

The firmware's boot order changed. Pick systemLinux in the firmware boot menu, or fix the order there, or with efibootmgr (efibootmgr lists the entries, sudo efibootmgr -o 0001,0000 sets the order). Installing the fallback (--removable) helps with firmware that forgets entries.

"error: unknown filesystem"

The partition in search or set root is wrong, or its module is missing: add insmod ext2 (ext4), insmod xfs, insmod btrfs or insmod fat.
