5. Entering the new system

Related articles
  • Recovery
  • get
  • Ports tree

    2. 1.2 Kernel file systems
  2. 2 Entering
  3. 3 Updating the ports tree

chroot runs a shell whose / is the new system on /mnt. Everything you do in it happens to the installed system: you run its programs, its get, its passwd. The kernel is still the live system's, so the new system needs the kernel's file systems (/dev, /proc, /sys) mounted inside it first.

Preparing

DNS

Copy the live system's name server settings, so downloads work inside the chroot:

# cp --dereference /etc/resolv.conf /mnt/etc/

Kernel file systems

# mount --types proc /proc /mnt/proc
# mount --rbind /sys /mnt/sys && mount --make-rslave /mnt/sys
# mount --rbind /dev /mnt/dev && mount --make-rslave /mnt/dev
# mount --types tmpfs tmpfs /mnt/run

--rbind also brings along what is mounted below (/dev/pts, the EFI variables in /sys/firmware/efi/efivars), and --make-rslave makes sure that unmounting them later does not unmount them in the live system too.

Entering

# chroot /mnt /bin/bash
# source /etc/profile
# export PS1="(chroot) $PS1"

The prompt now starts with (chroot), so you can always tell where you are. If you leave the chroot (exit, or a reboot of the live system in the middle of the install), mount the file systems again as in chapter 3 and repeat this chapter.

Note: dinit is not running inside the chroot, so dinitctl start and dinitctl enable do not work there. Enabling a service is only a link in /etc/dinit.d/boot.d, which the Handbook makes by hand (see dinit).

Updating the ports tree

The stage carries the ports tree of its release in /usr/ports. Fetch the newest one:

(chroot) # get sync

This is optional; the tree from the stage works. Without a network, skip it.

Building software now

You can already install software with get inside the chroot, for example an editor you prefer to nano:

(chroot) # get install vim

Builds run on the live system's kernel but use the new system's compilers and libraries, so the result is the same as building after the first boot. Big things such as a desktop are easier after the first boot, when you are no longer tied to the live system.
