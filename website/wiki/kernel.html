systemLinux ships the newest Ubuntu generic kernel of the day of the release: a well-tested kernel with nearly every driver built as a module. The ISO and the stage carry the same kernel.

Files

PathContents
/boot/vmlinuzthe kernel
/boot/initrd.imgthe initramfs
/usr/lib/modules/VERSION/the modules (/lib/modules is the same directory)
$ uname -r                               # the running kernel's version

Modules

eudev loads the driver for each device when it appears, so normally there is nothing to do.

TaskCommand
Loaded moduleslsmod
Information and options of a modulemodinfo MODULE
Load / unloadsudo modprobe MODULE / sudo modprobe -r MODULE
Which driver a PCI device useslspci -k (after sudo get install pciutils)

Options and blacklisting

Files in /etc/modprobe.d/*.conf set module options and stop modules from loading:

# /etc/modprobe.d/local.conf
options snd_hda_intel power_save=1
blacklist pcspkr                 # no more beeps
install nouveau /bin/false       # never load nouveau, not even as a dependency

Loading a module at every boot

For a module no device asks for, add a small dinit service:

# /etc/dinit.d/modules
type = scripted
command = /usr/bin/modprobe -a tcp_bbr v4l2loopback
depends-on = early-filesystems

and sudo dinitctl enable modules.

Kernel parameters

Options for the kernel itself go on its command line, in /boot/grub/grub.cfg. See Kernel parameters. Settings that can change at run time are in /proc/sys: sysctl -a lists them, sudo sysctl vm.swappiness=10 sets one.

Updating the kernel

Each release has a newer kernel. Until there is a linux port, take it from the new release's stage tarball: the kernel, the initramfs and the modules, nothing else. Keep the old kernel as a fallback.

$ cd /var/tmp
$ curl -LO https://github.com/tortr-rs/systemLinux/releases/download/vNEW/systemLinux-stage-NEW-x86_64.tar.xz
$ curl -LO https://github.com/tortr-rs/systemLinux/releases/download/vNEW/systemLinux-stage-NEW-x86_64.tar.xz.sha256
$ sha256sum -c systemLinux-stage-NEW-x86_64.tar.xz.sha256
$ sudo cp /boot/vmlinuz /boot/vmlinuz.old
$ sudo cp /boot/initrd.img /boot/initrd.img.old
$ sudo tar -xpf systemLinux-stage-NEW-x86_64.tar.xz -C / --numeric-owner ./boot/vmlinuz ./boot/initrd.img ./usr/lib/modules

Replace NEW with the version, for example 0.2.6. Then add an entry for the old kernel to /boot/grub/grub.cfg (a copy of the normal entry with vmlinuz.old and initrd.img.old), and reboot. Once the new kernel works, delete the old module directory: ls /usr/lib/modules, then sudo rm -r /usr/lib/modules/OLD-VERSION.

Warning: Do not delete the running kernel's modules (uname -r) before you have rebooted into the new one.

Other kernels

Any kernel that has the drivers for your disk and file system can boot systemLinux. Building one yourself means making an initramfs for it too, which systemLinux has no tool for yet; a kernel with your disk controller and root file system built in (not as modules) boots without one: leave out the initrd line in GRUB and add root=/dev/sda2 init=/usr/bin/dinit (the kernel itself only understands device names and PARTUUID=, not UUID=).
