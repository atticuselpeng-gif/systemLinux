/etc/fstab lists the file systems the system mounts at boot. The initramfs mounts the root file system; the mount-fstab service then runs mount -a and swapon -a for everything in /etc/fstab.

Format

One file system per line, six fields separated by spaces or tabs:

# <file system>   <mount point>  <type>  <options>          <dump>  <pass>
UUID=0f4c...e1      /              ext4    defaults,noatime   0       1
UUID=A1B2-C3D4      /boot/efi      vfat    umask=0077         0       2
UUID=7a9d...44      none           swap    defaults           0       0
file system
what to mount. UUID=... (recommended), LABEL=..., PARTUUID=... or a device such as /dev/mapper/root.
mount point
where; none for swap
type
ext4, vfat, xfs, btrfs, swap, tmpfs, nfs, ... (auto to detect)
options
comma-separated mount options; defaults if none
dump
for the old dump backup tool; always 0
pass
order for file system checks: 1 for root, 2 for the others, 0 never
Note: systemLinux does not check file systems at boot yet; the pass field is kept for tools that read it. Check an unmounted ext4 file system by hand with e2fsck -f /dev/sdXN, for example from the live ISO.

Finding UUIDs

$ lsblk -f
$ blkid -s UUID -o value /dev/sda2

Useful options

OptionEffect
noatimedo not write access times on every read (faster, less wear on SSDs)
nofailboot even if the device is missing (USB disks, network shares)
noautodo not mount at boot; mount /mnt/backup mounts it later
roread-only
usernormal users may mount it
umask=0077(FAT) only root can read the files: right for the EFI System Partition
uid=1000,gid=1000(FAT, exFAT, NTFS) the files belong to that user
discardtrim SSD blocks immediately (a weekly fstrim -a is usually better)

Examples

# a second disk for data, owned by root, mounted at /data
UUID=...   /data          ext4   defaults,noatime         0 2
# a USB disk that may be missing
UUID=...   /mnt/backup    ext4   defaults,nofail,noatime  0 2
# a tmpfs of 8 GB for builds (TMPDIR=/var/tmp/build get install ...)
tmpfs      /var/tmp/build tmpfs  size=8G,mode=1777        0 0

After editing, check the file and mount the new entries without rebooting:

$ sudo findmnt --verify
$ sudo mount -a
Warning: A mistake in the line for a file system that must be there (without nofail) does not stop the boot, but leaves it unmounted. Always run findmnt --verify.
