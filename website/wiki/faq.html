What is systemLinux?

A small x86_64 GNU/Linux distribution: GNU userland, dinit as init, no systemd, the newest kernel, and software built from source on your own machine with get. Nobody owns it and nobody profits from it.

Why no systemd?

To keep the system small and understandable. dinit starts services in parallel and supervises them, eudev manages devices, and the rest (logins, the runtime directory, the session bus) is done by small, separate pieces. See dinit and Graphical session.

Is there a binary package repository?

No, and there will not be one: ports are always built from source on your computer. The base system itself comes prebuilt (the stage tarball), and -bin ports install a project's own official builds (Firefox, the JetBrains IDEs, ...).

How long do builds take?

Small tools take seconds to a minute. A Sway desktop with Mesa and LLVM takes hours on a laptop the first time. Firefox from source takes hours; firefox-bin takes a minute.

How do I update the system?

Software from ports: get sync, then rebuild what you want with get install -f. The base system and kernel: see System maintenance. A get upgrade and base packages as ports are planned.

Which desktops work?

Sway and i3 are the documented ones. KDE Plasma is the goal for version 1.0.

Does it use musl?

Not yet: the base system uses glibc. A base built from source on musl is planned.

Does it work with Secure Boot?

No. The bootloader is not signed; turn Secure Boot off.

Does NVIDIA's driver work?

No, only the open nouveau driver. See Graphics drivers.

Which architectures?

x86_64 only.

Handbook install or quick install?

The Handbook gives an ordinary writable system you understand completely, and is where systemLinux is going. The quick installer is faster but still makes the older image install.

How can I help?

Test ports and report failures, fix recipes, write new ports, improve this wiki. See Contributing.
