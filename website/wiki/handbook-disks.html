Warning: Partitioning and formatting destroy the data on the partitions you touch. Back up first. Read the lsblk output twice before every command that names a disk.

Finding the disk

# lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,MOUNTPOINTS
NAME        SIZE TYPE FSTYPE   LABEL       MOUNTPOINTS
sda       476.9G disk
nvme0n1   238.5G disk
sdb        14.9G disk iso9660  SYSTEMLINUX

The stick you booted from has the label SYSTEMLINUX. In the examples below the target disk is /dev/sda; set a variable so the commands are easy to adapt:

# DISK=/dev/sda

To install next to Windows or another Linux without erasing the disk, read Dual boot first and skip the "new partition table" steps.

Choosing a layout

All layouts use a GPT partition table. Pick the one that matches how you booted (UEFI or BIOS):

UEFI

PartitionSizeTypeFile systemMount point
/dev/sda11 GiBEFI SystemFAT32/boot/efi
/dev/sda2rest of the diskLinux filesystemext4/

Legacy BIOS

PartitionSizeTypeFile systemMount point
/dev/sda11 MiBBIOS bootnonenone (GRUB writes its code here)
/dev/sda2rest of the diskLinux filesystemext4/

Both (a disk that boots either way)

Make the 1 MiB BIOS boot partition first, then the EFI System Partition, then root. This is what systemlinux-install does, and it lets you move the disk to any computer.

Optional partitions

  • Swap. Not needed: systemLinux turns on 4 GB of compressed swap in memory (zram) at every boot. A swap partition helps when you build big programs with little RAM; see Swap.
  • Separate /home. Keeps your files when you reinstall. Make root at least 40 GB then.
  • Separate /boot. Needed with an encrypted root, see below.
Note: The live system can create ext4, FAT32 and swap. Its initramfs can also mount XFS, Btrfs and F2FS roots, but mkfs.xfs and mkfs.btrfs are not on the ISO, so this Handbook uses ext4.

Partitioning

With sfdisk (scripted)

sfdisk reads the whole layout from one line each. U is the EFI System type, L Linux filesystem, S Linux swap; the long number is the BIOS boot type. A size left empty means "the rest of the disk".

# wipefs -a "$DISK"                     # removes old partition tables and signatures

# UEFI: ESP + root
# printf 'label: gpt\n,1G,U\n,,L\n' | sfdisk "$DISK"

# legacy BIOS: BIOS boot + root
# printf 'label: gpt\n,1M,21686148-6449-6E6F-744E-656564454649\n,,L\n' | sfdisk "$DISK"

# both: BIOS boot + ESP + root
# printf 'label: gpt\n,1M,21686148-6449-6E6F-744E-656564454649\n,1G,U\n,,L\n' | sfdisk "$DISK"

# UEFI with an 8 GiB swap partition: ESP + swap + root
# printf 'label: gpt\n,1G,U\n,8G,S\n,,L\n' | sfdisk "$DISK"

With cfdisk (menus)

cfdisk "$DISK" shows the disk and lets you create partitions with the arrow keys. On an empty disk it asks for the label type: choose gpt. Use New for each partition, Type to set "EFI System", "BIOS boot" or "Linux swap" (new partitions are "Linux filesystem"), then Write and type yes. fdisk "$DISK" works too if you prefer its one-letter commands (g new GPT, n new partition, t type, w write).

Check the result:

# lsblk "$DISK"
# fdisk -l "$DISK"

From here on the examples use the UEFI layout: ESP=/dev/sda1 and ROOT=/dev/sda2. With the "both" layout they are /dev/sda2 and /dev/sda3; on NVMe /dev/nvme0n1p1 and so on.

# ESP=/dev/sda1 ROOT=/dev/sda2

Creating file systems

# mkfs.ext4 -L systemLinux "$ROOT"
# mkfs.fat -F 32 -n EFI "$ESP"           # UEFI only, and only for a new ESP: never reformat Windows' ESP

With a swap partition (in the swap layout above, /dev/sda2 is swap and /dev/sda3 root):

# mkswap -L swap /dev/sda2
# swapon /dev/sda2

Encryption (optional)

To encrypt the root partition with LUKS, add a separate, unencrypted /boot partition of 1 GiB before root. GRUB 2.12 cannot open LUKS2 volumes made with cryptsetup's default key function (Argon2), so the kernel and initramfs stay on /boot and the initramfs unlocks root. The UEFI layout becomes:

# printf 'label: gpt\n,1G,U\n,1G,L\n,,L\n' | sfdisk "$DISK"
# ESP=/dev/sda1 BOOT=/dev/sda2 ROOT=/dev/sda3
# mkfs.fat -F 32 -n EFI "$ESP"
# mkfs.ext4 -L boot "$BOOT"
# cryptsetup luksFormat "$ROOT"           # type YES, then the passphrase twice
# cryptsetup open "$ROOT" root
# mkfs.ext4 -L systemLinux /dev/mapper/root

From now on mount /dev/mapper/root where the Handbook says $ROOT, and keep the UUID of the encrypted partition (blkid -s UUID -o value /dev/sda3) for the bootloader. The initramfs recognises a LUKS partition by itself and asks for the passphrase at boot. More in Disk encryption.

Warning: A forgotten passphrase cannot be recovered. Nobody can get your data back, including you.

Mounting

Mount the root file system on /mnt. The rest is mounted after the stage is extracted.

# mount "$ROOT" /mnt                       # encrypted: mount /dev/mapper/root /mnt
# mkdir -p /mnt/boot
# mount "$BOOT" /mnt/boot                  # only with a separate /boot partition
# mkdir -p /mnt/home && mount /dev/sdXN /mnt/home   # only with a separate /home
Note: Do not mount the EFI System Partition yet. It is FAT32, which cannot store file owners, and the stage would try to set them. Chapter 6 mounts it.
