Package profiles

Related articles
  • get
  • Graphical session
Contents
  1. 1 Available profiles
  2. 2 Installing a profile
  3. 3 How they are made

A package profile is a prebuilt part of the base system, published as profile-NAME.tar.xz with every release. Profiles keep the ISO small: what a console system does not need is left out of the image and unpacked later with get profile.

Available profiles

ProfileContentsIn the stage and the ISO
base-systemthe core systemyes
network-runtimecurl, wget, tar, xz, bzip2, gzip, CA certificatesyes
build-toolchainGCC, binutils, make and the rest of the compiler stackyes
common-build-depsCMake, Meson, Ninja, pkgconf, autotools and common headersyes
lang-runtimesPython, Perl and other language runtimesyes
desktop-runtimefonts, icon and GTK themes, X11 data, .desktop files, MIME datano

The profiles marked "yes" are already installed; they are published so they can be put back if something removed their files. desktop-runtime is the one you install yourself, before a graphical session: without it, graphical programs find no fonts.

Installing a profile

$ sudo get profile desktop-runtime

get downloads the profile of the release your system was installed from (and the profiles it requires), checks the checksums and unpacks it over /. To use another location, set GET_PROFILE_URL to the folder that holds the profile-*.tar.xz files.

Note: Profiles are not tracked by get list and cannot be removed with get remove; they are part of the base system.

How they are made

Each profile is a list of paths in profiles/NAME.list in the repository. @keep marks a profile that stays in the image and @requires NAME a profile that must be installed first. The ISO build packs every profile from the base system tree and strips the ones without @keep from the image (see Building the ISO).
