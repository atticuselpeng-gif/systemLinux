sudo

Related articles
  • Users and groups
  • 6. Configuring the system
Contents
  1. 1 Usage
  2. 2 Configuration
  3. 3 doas
  4. 4 Troubleshooting

sudo runs one command as root (or another user) after asking for your password. It is part of the base system.

Usage

$ sudo get install htop                  # one command as root
$ sudo -i                                # a root login shell
$ sudo -u alex whoami                    # as another user
$ sudo -l                                # what you are allowed to run

After the first password, sudo does not ask again for a few minutes in the same terminal.

Configuration

The rules are in /etc/sudoers and in the files under /etc/sudoers.d/. Do not edit them directly: a syntax error locks everyone out of sudo. Use visudo, which checks the file before it saves:

# EDITOR=nano visudo -f /etc/sudoers.d/10_wheel

Common rules:

%wheel ALL=(ALL:ALL) ALL                  # members of wheel may run anything, with their password
%wheel ALL=(ALL:ALL) NOPASSWD: ALL        # ... without a password
alex   ALL=(root) /usr/bin/dinitctl       # alex may run only dinitctl as root

Files in /etc/sudoers.d/ must belong to root and have mode 440; files whose name contains a dot or ends in ~ are ignored. Check everything with visudo -c.

The quick installer and systemlinux-provision create /etc/sudoers.d/10_wheel with the first rule. In a Handbook install you create it yourself (chapter 6).

doas

If you prefer OpenBSD's smaller doas, it is in the ports tree:

$ sudo get install opendoas
$ echo 'permit persist :wheel' | sudo tee /etc/doas.conf
$ sudo chmod 400 /etc/doas.conf

Troubleshooting

  • "alex is not in the sudoers file": add the user to wheel (as root: usermod -aG wheel alex, then log in again) and make sure the %wheel rule exists.
  • "operation not permitted": the sudo program lost its setuid bit, which happens with installs from systemLinux 0.2.3 and older. Install a newer release.
  • A broken sudoers file: log in as root (or use Recovery) and fix it with visudo.
