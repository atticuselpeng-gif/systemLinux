systemLinux can share a disk with Windows or another Linux system. It does not resize partitions for you: you make room with the other system's own tools first, then install into the free space.

Warning: Back up the other system before you change its partitions.

Before you start

  • Find out how the other system boots. On Windows, System Information (msinfo32) shows "BIOS Mode: UEFI" or "Legacy". Install systemLinux in the same mode, and boot the ISO in that mode.
  • Windows: turn off Fast Startup (Control Panel, Power Options, "Choose what the power buttons do"), so Windows really shuts down and leaves its partitions consistent. If BitLocker is on, have the recovery key ready: firmware changes can make Windows ask for it.
  • Turn off Secure Boot in the firmware settings.

Making room

Windows: open Disk Management (diskmgmt.msc), right-click the Windows partition (usually C:), choose Shrink Volume and enter how much to free, at least 20 GB. Leave the space unallocated.

Linux: shrink a partition with GParted from a live system of that distribution. XFS cannot shrink; you have to back up, recreate it smaller and restore.

Partitioning the free space

Boot the systemLinux ISO and create a new partition in the free space with cfdisk /dev/sda (select "Free space", New, Write). Do not create a new partition table, and do not touch the existing partitions. Note the new partition's name, then follow the Handbook from Creating file systems on, with these differences:

  • UEFI: reuse the existing EFI System Partition. Find it with lsblk -o NAME,SIZE,FSTYPE,PARTTYPENAME (type "EFI System", FAT32, usually 100 to 500 MB). Do not format it. Mount it on /boot/efi in chapter 6 as usual. In chapter 8, leave out the --removable command.
  • BIOS: GRUB is written to the disk's first sector and replaces the other system's bootloader there; add a menu entry to start the other system from GRUB (below). A GPT disk needs a 1 MiB BIOS boot partition; an MBR disk does not.

The quick installer does the same with systemlinux-install --partition /dev/sdaN (and --esp when there are several EFI System Partitions); see Quick install.

GRUB entries for other systems

systemLinux has no os-prober; add the entries to /boot/grub/grub.cfg yourself.

Windows (UEFI)

menuentry "Windows" {
    insmod part_gpt
    insmod fat
    search --no-floppy --fs-uuid --set=root ESP-UUID
    chainloader /EFI/Microsoft/Boot/bootmgfw.efi
}

ESP-UUID is the EFI System Partition's UUID: blkid -s UUID -o value /dev/sda1.

Windows (BIOS)

menuentry "Windows" {
    insmod part_msdos
    insmod ntfs
    search --no-floppy --fs-uuid --set=root WINDOWS-UUID
    chainloader +1
}

Another Linux (UEFI)

Start its own bootloader, so its kernel updates keep working:

menuentry "Arch Linux" {
    insmod fat
    search --no-floppy --fs-uuid --set=root ESP-UUID
    chainloader /EFI/GRUB/grubx64.efi
}

Look in /boot/efi/EFI/ for the right folder name. You can also skip GRUB's menu entirely and choose the system in the firmware's boot menu.

Shared files and the clock

  • Windows keeps the hardware clock in local time; see System time.
  • To read the Windows partition, install NTFS support: sudo get install ntfs-3g, then sudo ntfs-3g /dev/sda3 /mnt/windows. Never write to it while Windows is hibernated or Fast Startup is on.
  • A shared exFAT partition works for both: sudo get install exfatprogs to create one.
