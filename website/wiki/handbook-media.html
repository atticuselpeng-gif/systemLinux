Hardware requirements

MinimumRecommended
CPUany 64-bit x86 processor (x86_64)4 cores or more: every package is built from source
Memory2 GB8 GB or more (big C++ programs need about 2 GB per build job)
Disk10 GB40 GB or more if you will build a desktop and a browser from source
FirmwareUEFI or legacy BIOS. On UEFI, Secure Boot must be off: the bootloader is not signed.
NetworkNot needed to install from the ISO. Needed to download the stage tarball, ports and sources.

Intel, AMD and the open NVIDIA driver (nouveau) are supported for graphics; NVIDIA's own driver is not. Most Wi-Fi cards need firmware, see Firmware.

Downloading

Everything is on the latest release page:

FileWhat it is
systemLinux-VERSION-x86_64.isoThe live and installer ISO. You boot it to install.
systemLinux-stage-VERSION-x86_64.tar.xzThe stage tarball: the whole system as one archive. You can download it later from the live system (chapter 4); you do not need it now.
*.sha256, SHA256SUMSChecksums of every file.
profile-*.tar.xzPackage profiles, unpacked later with get profile.
ports.tar.xzThe ports tree, downloaded by get sync.

Checking the download

Check the ISO against its checksum before you use it. On Linux, in the download folder:

$ sha256sum -c systemLinux-0.2.5-x86_64.iso.sha256
systemLinux-0.2.5-x86_64.iso: OK

Anything other than OK means the file is damaged or not the one that was published: download it again. On Windows run certutil -hashfile systemLinux-0.2.5-x86_64.iso SHA256 in a command prompt and compare the output with the .sha256 file; on macOS use shasum -a 256.

Writing a USB stick

Warning: Writing the ISO erases everything on the stick.

Linux

Plug the stick in and find its name with lsblk: it is the disk with the stick's size, for example /dev/sdb. Use the whole disk, not a partition (/dev/sdb, not /dev/sdb1):

$ lsblk
$ sudo dd if=systemLinux-0.2.5-x86_64.iso of=/dev/sdb bs=4M status=progress conv=fsync

Wait until dd returns to the prompt before you pull the stick out.

Windows

Use Rufus and choose DD image mode when it asks, or balenaEtcher.

macOS

$ diskutil list                                 # find the stick, e.g. /dev/disk4
$ diskutil unmountDisk /dev/disk4
$ sudo dd if=systemLinux-0.2.5-x86_64.iso of=/dev/rdisk4 bs=4m

Ventoy

The ISO also boots from a Ventoy stick: copy the .iso file onto it. Several systemLinux ISOs on one Ventoy stick are fine; each one finds its own files.

Virtual machines

Attach the ISO as a CD and give the machine an empty disk of at least 20 GB. With QEMU:

$ qemu-img create -f qcow2 disk.qcow2 40G
$ qemu-system-x86_64 -enable-kvm -cpu host -m 4G -smp 4 \
    -drive file=disk.qcow2,if=virtio -cdrom systemLinux-0.2.5-x86_64.iso -nic user

That boots in legacy BIOS mode. For UEFI, add the OVMF firmware, for example -bios /usr/share/edk2/x64/OVMF.4m.fd (the path depends on your distribution). VirtualBox and VMware work too: choose "Other Linux (64-bit)" and turn on EFI in the machine settings if you want UEFI.
