4. Installing the stage

Related articles

  • 5. Entering the new system

Contents
  1. 1 Option A: downloading the stage tarball
    1. 1.1 Checking it
    2. 1.2 Extracting it
  2. 2 Option B: copying the system from the ISO (offline)
  3. 3 What is in it

A stage tarball is the complete systemLinux base system packed into one archive: dinit, the kernel and its modules, the initramfs, the GNU tools, NetworkManager, the compilers and build tools, get and the ports tree. You extract it onto the root partition and the system is there; the next chapters configure it.

It is the same system the live ISO runs, so there are two ways to get it: download the tarball (the normal way), or copy it from the ISO when you have no network.

Option A: downloading the stage tarball

Download it straight onto the new root file system. The live system keeps its files in memory, which is too small for the tarball.

# cd /mnt
# VER=$(cat /usr/share/systemlinux/image-version)    # the live system's version, e.g. 0.2.5
# URL=https://github.com/tortr-rs/systemLinux/releases/download/v$VER
# curl -LO $URL/systemLinux-stage-$VER-x86_64.tar.xz
# curl -LO $URL/systemLinux-stage-$VER-x86_64.tar.xz.sha256

Use the version of the ISO you booted, so that the stage matches what you tested in the live system. A newer stage from a newer release works too; look at the release page for its name.

Checking it

# sha256sum -c systemLinux-stage-$VER-x86_64.tar.xz.sha256
systemLinux-stage-0.2.5-x86_64.tar.xz: OK

Do not go on unless it says OK.

Extracting it

# tar -xpf systemLinux-stage-$VER-x86_64.tar.xz --xattrs-include='*.*' --numeric-owner -C /mnt
# rm systemLinux-stage-$VER-x86_64.tar.xz*
-x -p -f FILE
extract, keeping file modes exactly (setuid programs like su and sudo need this)
--xattrs-include='*.*'
restore extended attributes as well
--numeric-owner
use the owner numbers stored in the archive, not the live system's user names

Extracting takes a few minutes and writes a few gigabytes.

Option B: copying the system from the ISO (offline)

The ISO carries the same system as a compressed image, /live-medium/live/rootfs.squashfs. Mount it and copy it over:

# mkdir -p /tmp/image
# mount -o loop,ro /live-medium/live/rootfs.squashfs /tmp/image
# cp -a /tmp/image/. /mnt/
# umount /tmp/image

Copy the image, not the running live system (/): the running system has the live system's changes in it, such as the automatic root login.

Note: If you started the ISO with copy to RAM and pulled the stick out, /live-medium is gone. Plug the stick back in, or use option A.

What is in it

# ls /mnt
bin  boot  dev  etc  home  lib  lib64  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
# ls /mnt/boot
initrd.img  vmlinuz
  • /boot/vmlinuz and /boot/initrd.img: the kernel and the initramfs (chapter 7).
  • /usr/lib/modules/: every kernel module.
  • /usr/ports: the ports tree of this release.
  • /etc/dinit.d: the service descriptions (dinit).
  • /bin, /sbin and /lib are links into /usr.
