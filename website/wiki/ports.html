The ports tree is the collection of recipes get builds software from. It lives in /usr/ports on every system and in the ports/ folder of the repository. Browse it on the Packages page.

Layout

Each port is a folder CATEGORY/NAME with at least a recipe file:

/usr/ports/
├── dev-apps/neovim/recipe
├── sys-app/seatd/
│   ├── recipe
│   └── dinit/seatd          # a dinit service, installed into /etc/dinit.d
└── sys-app/greetd/
    ├── recipe
    ├── dinit/greetd
    └── files/etc/greetd/config.toml   # copied into the package as it is
CategoryContents
sys-appsystem tools, daemons, file system utilities, firmware
dev-appsdeveloper tools, editors, build systems
dev-libslibraries
dev-python, dev-perlPython and Perl modules (generated from PyPI and CPAN)
langcompilers and language runtimes
netnetworking
x11graphical programs, Wayland and X11
mediaaudio and video
text, shells, sec, db, sci, gameswhat their names say

A recipe

version=0.9.1
description=Seat management daemon (lets Wayland compositors use the GPU and input)
url=https://git.sr.ht/~kennylevinsen/seatd/archive/0.9.1.tar.gz
sha256=819979c922a0be258aed133d93920bce6a3d3565a60588d6d372ce9db2712cd3
build=meson
configure_args=-Dlibseat-logind=disabled -Dserver=enabled -Dman-pages=disabled -Dexamples=disabled
requires=dev-apps/meson dev-apps/ninja
check=pkgconfig:libseat

url is the source, sha256 its checksum, build the build system, requires the dependencies, and check tells get how to see that the base system already provides the package. A port without a url is a meta port that only pulls in others. The Packaging guide documents every key.

Keeping it up to date

sudo get sync downloads the ports tree of the latest release (ports.tar.xz), checks its checksum and replaces /usr/ports with it. To follow the development version instead, use a git checkout:

$ git clone https://github.com/tortr-rs/systemLinux ~/systemLinux
$ sudo GET_PORTS=$HOME/systemLinux/ports get install NAME

Unverified ports

Many ports were written or generated in bulk and have not all been built on a real system yet. If one fails, report it; if you fix it, send the fix (Contributing).
